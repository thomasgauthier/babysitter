## Session

- Model: `qwen3.5-9b-ud`
- Goal: build a bounded TIC-80 cars game and verify it with `tic80ctl`
- Scope: one run with repeated Lua writes and visual playtest verification

## Outcome

- The model failed four Lua writes before a playable cart was produced.
- Early drafts used the wrong engine structure, wrong input API, and invalid Lua syntax.
- Load success was not enough; visual verification showed the car could still appear stationary even when the cart ran.

## Notes

- Exact fixes that worked were a `function TIC()` main loop, `btn(id)` input, moving state outside `TIC()`, and supplying the exact 96-character palette string.
- The model responds better to numbered technical nudges than to vague patience.
- Runtime verification is required here; `tic80ctl` success alone did not prove the game was actually playable.
